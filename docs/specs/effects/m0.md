# M0 — Compiler and recovery feasibility

M0's bounded investigation is complete. **The proposed full direct-style
`@safe pure nothrow @nogc` boundary has not passed its acceptance gate.** The
weak-purity bridge worked in the tested compiler configurations; no optimizer
miscompilation was observed. That result does not establish a language-level
guarantee for arbitrary impure handlers. The existing live supervision API also
fails the required safety, exception and allocation attribute checks.

This page holds the experiment and walkthrough evidence. [PLAN.md](./PLAN.md)
remains the milestone tracker. [SPEC.md §4.2](./SPEC.md#_4-2-attributes-ownership-and-the-purity-gate)
keeps the direct-style API conditional. No durable implementation has begun.

## 1. Reproduce the experiment

Sources are intentionally isolated from the proposed library:

- [bridge.d](./experiments/m0/bridge.d): opaque, noncopyable row; one purity cast;
  mutable receiver; handler invocation and latched stop.
- [probe.d](./experiments/m0/probe.d): runtime checks and compiler-negative cases.
- [run.d](./experiments/m0/run.d): the D matrix driver, including expected output
  assertions and rejection checks.
- [live_surface.d](./experiments/m0/live_surface.d): exact-expression checks
  against the actual `supervise` function. It does not create a scheduler or
  launch a child.

From the repository root, with the Nix development shell active:

```bash
cd docs/specs/effects/experiments/m0
dub run --single run.d -- /tmp/sparkles-effects-m0-results
```

Run the live-surface checks from the root:

```bash
dub run --compiler=ldc2 --single docs/specs/effects/experiments/m0/live_surface.d
dub run --compiler=dmd --single docs/specs/effects/experiments/m0/live_surface.d
```

The matrix invokes both compilers with `-preview=in -preview=dip1000 -g`.
Debug adds `-debug` (DMD) or `-d-debug` (LDC); checked adds `-O -inline` (DMD)
or `-O2 -enable-inlining` (LDC). Assertions remain enabled. Each configuration
runs with bridge inlining explicitly permitted and explicitly disabled.
`DebugEscape` is also run in every configuration, so the experiment checks the
language's debug relaxation rather than merely mentioning it.

The driver writes compiler version reports, all compiler diagnostics and runtime
output to the selected artifact directory. A negative case must fail compilation
with an error diagnostic; the inspected diagnostics name the expected purity,
visibility, copy, schema or function-attribute violation. A missing compiler,
missing import or linker failure is not an acceptable substitute. These are
experiments, not automatically discovered production unit tests.

## 2. Observations

Environment: Linux x86_64; DMD 2.112.1; LDC 1.42.0, based on DMD 2.112.1 and
LLVM 18.1.8. Run against the specification branch following `83043c1a0`, on
September 14, 2026.

| Probe                                                                    | DMD debug / checked | LDC debug / checked | Interpretation                                                              |
| ------------------------------------------------------------------------ | ------------------- | ------------------- | --------------------------------------------------------------------------- |
| Repeated identical arguments                                             | Pass / pass         | Pass / pass         | Distinct live calls execute                                                 |
| Discarded result                                                         | Pass / pass         | Pass / pass         | External output still occurs                                                |
| Aliased mutable row                                                      | Pass / pass         | Pass / pass         | Alias shares one state                                                      |
| Fresh state on another episode                                           | Pass / pass         | Pass / pass         | Both episodes produce the same values                                       |
| Mutable delegate context                                                 | Pass / pass         | Pass / pass         | Context increments survive; weak purity allows mutation                     |
| Stop latch and exception translation                                     | Pass / pass         | Pass / pass         | A caught, preallocated exception becomes a control result; later calls stop |
| Direct impure handler call without the cast                              | Reject / reject     | Reject / reject     | Ordinary purity checking is active                                          |
| Ambient clock and I/O                                                    | Reject / reject     | Reject / reject     | Outside debug, the restricted function rejects these calls                  |
| Raw handler escape and row copy                                          | Reject / reject     | Reject / reject     | Module privacy and disabled copying work for these cases                    |
| Serialize row as a durable value                                         | Reject / reject     | Reject / reject     | Explicit schema allowlist rejects it; this is not an inference from `pure`  |
| Throwing or allocating handler assigned to restricted handler type       | Reject / reject     | Reject / reject     | A purity cast alone cannot erase other attributes                           |
| Impure mutation inside `debug` in an `@safe pure nothrow @nogc` function | Executes / absent   | Executes / absent   | Debug purity relaxation is real                                             |

These results hold for both bridge-inlining settings: **80 compiler/runtime
checks passed**, comprising 16 successful executable runs and 64 expected
compilation rejections. Each normal run emits eight `effect:10` lines through
real C stdio, then:

```text
a=37 b=37 local=4,4 world=8 context=3,2
exception=-2 latched=-1
```

The debug-escape runs additionally print `debug-world=9` in debug builds and
`debug-world=8` in checked builds. The exception is allocated before entering
the test handler; the result does not imply arbitrary throwing/allocating
libraries can be made `@nogc` by catching their exceptions.

The actual live API reports, under both compilers:

```text
supervise: ordinary=true nothrow=false nogc=false safe=false
attributes=system
```

The positive ordinary-call check prevents these negative attribute results from
being explained by a wrong call signature. The public event sink is also an
unrestricted delegate. This experiment checks the current API surface; it does
not prove that a future audited implementation could never satisfy stronger
attributes. Achieving that would be new work, not mechanical capability
forwarding in M2.

### Generated-code inspection

With the bridge's default no-inline setting, generate its isolated artifacts:

```bash
ldc2 -preview=in -preview=dip1000 -O2 -enable-inlining --output-ll -c \
    -of=/tmp/sparkles-effects-m0-results/bridge.ll \
    docs/specs/effects/experiments/m0/bridge.d
dmd -preview=in -preview=dip1000 -O -inline -c \
    -of=/tmp/sparkles-effects-m0-results/bridge.o \
    docs/specs/effects/experiments/m0/bridge.d
objdump -d /tmp/sparkles-effects-m0-results/bridge.o
```

LDC's `Row.call` contains an indirect `call i32` to the handler, with a mutable
state pointer and the integer input. Its function-attribute set has `noinline`
and unwind/target metadata; it does not have `memory(none)` or a read-only memory
effect declaration. DMD's corresponding method contains an indirect
`call *%rax`. The stopped path returns without reaching that call. The matrix
separately exercises the inline-enabled version, including discarded calls.

The version-matched [DMD side-effect classifier][dmd-sideeffect] treats weakly
pure calls as potentially side-effecting. Its [purity classifier][dmd-funcsem]
weakens a method on a mutable receiver. This explains why replacing the bridge
with a strongly pure, context-free cast would be a materially different
experiment. The repository's `dmd-src` flake input is a LanguageServer fork and
was not treated as the exact source of the installed compilers; these citations
resolve the DMD 2.112.1 release tag to its commit.

## 3. What the observations do and do not establish

The mutable row is essential: it gives the compiler an argument through which
state changes are visible. An opaque constructor and no raw-handler accessor
also make accidental bypass harder. These properties passed the selected
negative and runtime cases. They are useful evidence in favor of this particular
implementation shape, and there is no basis here for claiming that DMD or LDC
elided its live operations.

The [D language rules][d-purity] nevertheless permit only pure calls from pure
functions, allow state mutation through mutable arguments, and explicitly relax
purity inside debug statements. Strongly pure functions can be memoized under
the documented conditions. Those rules do not grant a general external-I/O
exception merely because a function pointer was retyped. The experiment uses
such a retyping deliberately, so successful compilation does not discharge its
semantic obligation. The bridge reaches an ambient counter and external stdio,
not just journal state passed by reference.

The investigation therefore leaves the language-level justification **unproved**,
rather than claiming a demonstrated optimizer failure or universal impossibility.
No testing matrix could justify casting away `@safe`, `nothrow` or `@nogc` on
the existing supervisor. The concrete API mismatch and the missing semantic
argument mean the full EFF6 gate is not met.

The accepted four policy decisions do not depend on the choice of bridge. M1
extraction and M2 capability forwarding may proceed independently. M3 and later
must wait for an accepted program boundary or additional evidence that actually
discharges this one.

## 4. Protocol walkthroughs

These are manually derived transition traces, not tests against a durable
implementation. `I`, `R` and `C` denote committed intent, result and compensation
registration. Brackets denote one atomic append; “crash” discards volatile state.

| Case and durable prefix                                                 | Required next transition                                                                                                                                                       | Forbidden shortcut                                                              |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| `[I]`, world changed, crash before `[R,C]`                              | Run the recorded recovery class: manual pauses; deduplicated resubmits the same key; reconcile records a probe and either completes atomically, authorizes a repeat, or pauses | Treat missing result as proof no effect happened                                |
| `[R,C]` committed, acknowledgement lost                                 | Look up the original transaction ID; return its committed receipt and replay its result                                                                                        | Reinvoke the handler or register compensation twice                             |
| Wait open, cancel and input race                                        | The first committed resolution wins; cancellation of an unresolved wait atomically records command, cancelled result and resolution. Later delivery is `alreadyResolved`       | Accept input after committed cancellation merely because the token still exists |
| Forward results complete; compensation B succeeds, compensation A fails | Persist B's result and finished marker together. Pause on A's error. An explicit retry with remaining recorded budget schedules A's next attempt; B remains finished           | Restart the sweep at B, skip A, or retry A automatically                        |
| Fork audit committed in parent, crash before child creation             | Retry the same command ID and child ID; create or find the child's matching `RunCreated`; acknowledge only after durable publication                                           | Make a second child or consider parent audit alone successful publication       |

Two ambiguities were corrected in the normative text during this walkthrough:

1. Cancellation of a wait now shares the same atomic resolution discipline as
   input/deadline completion. A committed cancel/terminate excludes later input;
   an already committed input remains the historical answer, with cancellation
   delivered at the next boundary. Historical input cannot be rewritten.
2. Compensation attempts use **manual scheduling after a domain failure**, even
   while ordinary retryable activities may schedule automatically. Retries are
   still bounded by the policy stored in the compensation intent. Exhausting it
   leaves the sweep paused; it does not grant another attempt. This preserves
   the accepted explicit-only compensation policy and EFF22's explicit retry.

The walkthrough now gives a unique transition or explicit pause for each
selected state. It does not establish filesystem crash consistency, complete
state-machine coverage, or correctness under arbitrary concurrent commands.
Those remain the implementation gates in M3–M6.

## 5. Proposed boundary revision — awaiting acceptance

**Recommendation:** retain the replaying ordinary program, but make its row
purely consume history or return a request as data. Put effect execution in an
explicitly impure host driver. This proposal has not replaced EFF6.

The program-facing call returns a recorded value if available. At the live
frontier it stores the requested operation in the row and returns a typed
`needRequest` control result. The program propagates that result; the row latches
it, so ignored control cannot produce further requests. The host receives the
request after the program returns, commits its intent, executes the handler,
commits the outcome, and invokes the program again against the extended history.
The durable program remains its own resume function; no continuation is captured.

<!-- md-example-skip -->

```d
// Proposed shape only; no replacement library API is implemented by M0.
Advance!(Value, Error) advance(alias program, Registry, Input)(
    ref ReplayRow!Registry row, in Input input)
    @safe pure nothrow @nogc;

// Host owns scheduling, live handlers and persistence; attributes infer.
EpisodeResult!(Value, Error) drive(alias program, Store, Registry, Input,
    Value, Error)(ref Store store, ref Registry handlers, in Input input);
```

`ReplayRow` contains owned/borrowed data, a replay cursor and a pending request;
it contains no callable live handler or scheduler. `Advance` distinguishes
completed outcome, next request, waiting/control and divergence. Codecs on the
pure side keep the restricted attributes; the live driver is honest about its
actual attributes and does not retype arbitrary callbacks. Debug restrictions
remain an authoring rule even for this boundary.

The trade-off is explicit: naively replaying from entry for every newly completed
operation costs O(n²) total prefix visits for n sequential operations, rather
than one live pass. External operations may dominate that cost, but M0 has not
measured it. An optimization must not reintroduce hidden impurity or continuation
capture without its own accepted contract. An impure direct-style program with
pure helper functions is another option; it gives up static whole-program
purity. A compiler-specific weak-purity bridge is a third option, but requires
accepting a narrower compatibility promise and solving the supervisor attributes
separately. None is silently selected by a failed feasibility gate.
