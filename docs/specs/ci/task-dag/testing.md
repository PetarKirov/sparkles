# `apps/ci` commands — Testing and evidence

This page maps each requirement of [SPEC.md](./SPEC.md) to the tests that
falsify it. The generic executor's evidence lives in the
[task DAG's testing page](../../build-primitives/task-dag/testing.md), and the
build graph's in [its own](../../build-primitives/build-graph/testing.md).
Command tests run real `ci` invocations against fixture repositories and
compare plain transcripts, exit codes and the files left behind.

| Requirement | Oracle                                                                                                                                                                                                                                                                                                                                                                                                         |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CIC1        | Option-validation tests: zero and negative `--jobs`, `--dry-run --interlaced`, `SPARKLES_CI_JOBS` precedence.                                                                                                                                                                                                                                                                                                  |

| CIC5        | `repository_inputs.cic5`: over this repository, the files planning read, the toolchain's patterns, the planner's inputs and the working-directory names are workspace inputs, and a package outside the planner, documentation and a recipe tool are not (build graph oracle 20).                                                                                                                              |
| CIC6        | No test node has an incoming edge from another package's test; a stack-heavy test fails the `-t 1` leg.                                                                                                                                                                                                                                                                                                        |

| CIC12       | Under `--require-cached compile`, a run with one edited module fails exactly the compiles that read it: the owning package's with a `declared` miss explanation, each dependent's with a `manifest` one, both naming the module, and a run with no edit passes.                                                                                                                                                |

| CIC17       | `ci check --help` lists every check the hooks and workflows run; a bare group exits non-zero with its help.                                                                                                                                                                                                                                                                                                    |

| CIC19       | A scripted run's status lines: the heading, what ran with why, a failure with only the lines that explain it, the summary with reused and ran counts; at trace, the reused results and the unneeded fallback; every task row's columns aligned, clean and boxed; a log record as a line with its level as the verb.                                                                                            |

| CIC21       | A run across two worktrees runs each action in its own and orders them by an edge across; over a planted change, an action reading nothing it touches waits for its namesake and the rest do not; a real range's second commit reuses every action its first shares with it.                                                                                                                                   |
| CIC22       | `--memory-max` parses to the scope's limits and refuses what is not one; an action's process reads the `oom_score_adj` its run set; on a systemd host a contained run's scope has the limits, the memory and pids controllers for its children, `ci` in `supervisor` and each action's cgroup beside it; `--memory-max=none` runs unconfined                                                                   |
| CIC23       | Predictions come from the recorded peaks or each kind's default and the peaks file keeps the largest; the budget leaves `ci` at least 1 GiB and never takes more than half; the gate cancels under a floor, holds unbounded under a reserve, holds bounded over 10 % pressure, gives a 1 GiB `tmpfs` a 100 MiB reserve; the store is evicted by the deficit; a run reports the free space at its start and end |
