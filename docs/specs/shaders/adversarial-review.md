# `sparkles:shaders` — Adversarial review of sections 4–8

This review is the adversarial review the [Stage 0 gate](./PLAN.md#stage-0-specification)
requires: sections 4–8 of [`SPEC.md`](./SPEC.md) — the vocabulary, device
modules, fragment entry points, the build step and build integration — read
against the implementation at revision `5966597c7`, with the four worked
traces the gate names. It also checks every `verified` row of the
[evidence ledger](./testing.md#evidence-ledger) by opening the test it cites.

Each requirement was attacked with a concrete input, and the input was run
wherever that was cheap: the build step against `sparkles:ui`, and against
small probe packages written outside the repository for the purpose (their
sources are in [the appendix](#appendix-probe-packages)). Every claim below
cites a file and line at `5966597c7` or a command and its output. Section 9
was read only where sections 4–8 depend on it.

The outcome: 28 findings, two of them blockers. The two blockers are a
contradiction between the per-entry interface rule (`SHF2`) and the unit model
(`SHP3`), which the pinned compiler resolves silently and wrongly for a
two-entry unit, and a freshness stamp whose input set misses files the device
compilation reads, so `--if-stale` vouches for stale output. Fourteen major
findings follow, most of them a requirement the code or the pinned compiler
breaks with no diagnostic, or a ledger row that claims more than its test
asserts. This review proposes dispositions; it accepts nothing.

## Method

The review used the dev shell's toolchain: `ldc2-vulkan` (LDC 1.43.0 on LLVM
24.0.0git, at the `SHT1` pins, which the `dlang-nix` input's
`pkgs/default.nix:193` and `pkgs/llvm-spirv/default.nix:30` confirm),
SPIR-V Tools and SPIRV-Cross 1.4.357.0, glslang 16.4.0, and dub
1.42.0-beta.1. The build step was run as
`apps/shader-compile/build/shader-compile` (built by `dub run :shader-compile`)
so that its own exit status, not dub's, is reported. `dub test :shader-compile`
passed all seven tests (`Summary: 7 passed, 0 failed`). Scratch output went to
`/tmp`; nothing in the repository was modified except this file.

**Trace A′: two entries that disagree on ordinals.** Step 8 holds for
`sparkles:ui` by convention only. Probe P2 has two entries,
`first(@input vec4 fragColor, Sampler2D texB, @uniform float u)` and
`second(@input vec2 fragTexCoord, @input vec4 fragColor, Sampler2D texA, Sampler2D texB, @uniform float u)`.
The build exits 0. Its disassembly has one variable per name, shared by both
entries, each with one decoration:

```text
OpDecorate %fragColor Location 0
OpDecorate %texB Binding 1
OpDecorate %fragTexCoord Location 0
OpDecorate %texA Binding 1
```

For `second`, `SHF2` requires `fragColor` at location 1 and `texB` at binding 2. Instead two inputs share location 0 and two images share binding 1, and
neither `spirv-val` nor `glslangValidator` objects. This is R1.

can be accepted; a **major** finding is a contract the code or the pinned
compiler breaks without a diagnostic, a missing failure contract, or evidence
that claims more than exists; a **minor** finding is an ambiguity or a narrow
divergence; an **editorial** one changes wording only.

## Not covered

This review did not examine:

- Section 9 beyond the pin revisions: the CI legs that `SHT4` cites (Windows,
  aarch64 Linux and macOS) were not inspected, and no cross-platform output
  was compared (`SHT3`).
- Host/device numeric agreement (`SHV7`, `SHF4`): no generated shader was
  executed on a GPU or a software rasterizer.
- `SHF6`: no disassembly was searched for images in composites or in Function
  storage.
- `SHM3` and `SHM4`: no device-rule violation was seeded, and the editor
  analysis's mirror of the rules (`dmd_lsp.testing.dcompute.*`, `TGT7`) was
  not compared with the compiler.
- Concurrency beyond one process: several simultaneous runs against one output
  directory (`SHP8`) and parallel dependents (`SHB7`) were not exercised.
- The Nix packaging of prebuilt output (`nix/packages/ui-shaders.nix:52–58`)
  was read, not built. The claim at `testing.md:146` that CI builds the
  terminal-only examples in a sandbox without `ldc2-vulkan` was not traced to
  a specific job.
- Sections 1–3 and the cold read of the opening, which the gate lists
  separately.
- Publication validation: this page has not been added to
  `docs/.vitepress/sidebar.json` or to the `srcExclude` list in
  `docs/.vitepress/docs-config.json` (where the fuzzy review is listed), so
  `ci --check-docs-sidebar` will report it until one of them is.
