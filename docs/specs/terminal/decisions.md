# Decisions and open questions

The choices behind the terminal specification, and the questions it left
open. Numbering continues from the Android page's D1–D5
([android.md](./android.md#decisions)). A decision's state is `proposed`,
`accepted` or `superseded`; every `accepted` row was chosen by the repository
owner from the alternatives it lists.

## Open questions

| ID  | Question                                                                                                                         | Affects                 | Resolver / decision point                                                                                                                                                                                                                                |
| --- | -------------------------------------------------------------------------------------------------------------------------------- | ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OQ1 | Parse OSC 52/99/777/1 payloads in the host scanner or extend libghostty-vt's C API?                                              | `TPR2`, `TPR8`, `TPR20` | resolved: in the host scanner; the engine stays pinned ([Protocols](./protocols.md#resolved-questions))                                                                                                                                                  |
| OQ2 | Does the engine send a mode-2031 report when the mode is set?                                                                    | `TPR14`                 | resolved: no report when the mode is set, as in Ghostty and libghostty-vt ([Protocols](./protocols.md#resolved-questions))                                                                                                                               |
| OQ3 | Do autofill services show their dropdown anchored to a 1×1 transparent view?                                                     | `TSE8`                  | answered in M5: Google's service (the device default) offers its passwords as inline suggestions in Gboard's strip, so the 1×1 field's size does not matter there; a service drawing a dropdown is untested                                              |
| OQ4 | Can a NativeActivity read the intent of a notification tap without Java?                                                         | `TPR12`                 | answered in M5: no — after a tap `getIntent()` and the task's `baseIntent` both lack the extra; the tap is inferred from the auto-cancelled notification ([`TPR12`](./protocols.md))                                                                     |
| OQ5 | Where does the documentation build stage the licence files the credits include, and how does a local `yarn docs:build` get them? | `TPG13`, `TPG16`        | resolved in M10: the `.#credits` derivation stages them from each component's source; `docs:build` copies them, git-ignored, through `docs/scripts/build-credits.sh`, and the APKs bundle the same derivation                                            |
| OQ6 | Which tree-sitter grammars does the terminal APK carry?                                                                          | `TDV1`                  | resolved in M11: a common subset — markdown and its inline grammar, D, C, Bash, Nix, JSON, YAML, TOML, Python — parsers as native libraries, queries extracted with the fonts (`terminal.nix` `viewerGrammars`); any other text file opens unhighlighted |
