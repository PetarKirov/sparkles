# `hue --gui` — Feature Requirements (raylib GPU window)

_**Status:** living inventory · **Date:** 2026-08-29 · **Scope:** what the
**raylib GPU window owns and a terminal cannot** — the window itself, font
loading and atlases, GPU-specific rendering, fullscreen, and procedural
box-drawing. Everything a viewer does at a given interaction tier, on any
canvas, moved to [viewer.md](./viewer.md); this file is the raylib backend — `apps/hue/src/gui.d` (window + interaction + paint),
`gui_preview.d` (markdown model → wrapped-line layout), `gui_ansi.d` (` ```ansi `
fence decode), `gui_text.d` (pure metrics/search) — plus the shared libraries it
drives: `sparkles:raylib-text` (fonts, glyph draw, procedural box-drawing),
`sparkles:ghostty` (off-screen VT), `sparkles:syntax` (the markdown model), and
`sparkles:ui` (the widget toolkit, including the table component)._

Compiled into hue's **default** build (the GUI backend is included by default —
[`BLD1`](./feature-requirements.md#build-and-packaging-bld)); a raylib-/ghostty-free
variant is the `no-gui` config ([`BLD2`](./feature-requirements.md#build-and-packaging-bld)).
The window opens automatically when a display is detected and can be forced or
suppressed with `--gui`/`--no-gui` (general [`MOD6`](./feature-requirements.md#output-mode-dispatch-mod)).
Status scheme and ID conventions: see the [overview](./index.md). App-wide
behaviour (source, engine, themes) is in
[feature-requirements.md](./feature-requirements.md); this doc covers only the
GUI. The entry point is `gui.runGui`.

## Design & scope (issue [#121](https://github.com/PetarKirov/sparkles/issues/121))

`hue --gui` is a **third consumer of hue's identical `(source, events, theme)`
triple** — the same triple `renderAnsi`/`renderHtml` consume — folded into raylib
draw calls instead of ANSI escapes or HTML markup. Nothing in hue's producer
pipeline changes (file read, `canonicalLanguage`, `highlightInjected`, theme
resolution, the plain-text fallback); only the sink is new. This is the
"styled runs as data" GPU backend `sparkles:syntax` was designed around
(`StyledSpan`/`byStyledSpan`/`ResolvedTheme` are its third-backend contract, and
`FontStyle` stays backend-neutral), and building it forced the two seams the
syntax spec reserved: `toRgb(Color, palette, default)` and `byStyledLine`.

**It is** a read-only, windowed, syntax-highlighted view with a live theme
previewer and a render-markdown.nvim-style markdown preview. **It is deliberately
not** a text editor, an incremental/LSP-backed surface, a terminal emulator, or
the Vulkan engine (#47) — it is the smallest honest GPU consumer of the styled-run
API, hosted in the app that already produces it. (The diff **write wave**
later adds **bounded editing surfaces** — an editable diff pane, a comment
composer — via the toolkit [editor component](../ui/editor.md)
([`UIA9`](./ui-architecture.md)); the not-an-editor-_app_ doctrine stands.)

> [!NOTE]
> Most GUI areas below — `SEL` (selection), `MDP` (markdown constructs), `NUM`
> (line numbers), `RND`/`VIW`/`WRP`/`NAV`/`SCB`/`FND`/`COD` — are **not
> GPU-specific**; they apply **best-effort** to the other interactive backends.
> For a **markdown** file the `MDP` preview is the **default** rendering in the
> terminal and HTML backends too (general [`MOD8`](./feature-requirements.md)),
> not GPU-only — the same widget-tree views, a different canvas.
> The full terminal port and its GUI→TUI parity map are in
> [tui.md](./tui.md); the HTML best-effort rows are `HTM3`–`HTM5` in the
> [general spec](./feature-requirements.md). This document remains the source of
> truth for the raylib backend itself.

## Font (`FNT`)

Fonts are owned by `sparkles:raylib-text` (`FontSet`); hue configures and drives it.

| ID    | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Status                     | Traces to                                                                                    |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- | -------------------------------------------------------------------------------------------- |
| FNT1  | `--font` must accept a path, a family, or a fontconfig **preference list** (first installed family wins); default leads with Nerd-Font coding families.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | full (`c2b49e99`)          | `FontSet.tryLoad(fontName)`; `defaultGuiFont`                                                |
| FNT2  | `--font-size` is in **points**; it must be converted to pixels at 96-DPI, matching the terminal.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | full (`c2b49e99`)          | `fontSizePx = fontSize*96/72`                                                                |
| FNT3  | Ctrl-`=` / Ctrl-`-` — and **Ctrl+wheel** (up grows, down shrinks) — must grow/shrink the font at runtime (reload faces + re-measure the cell), with a floor. A wheel frame takes ONE step whatever it accumulated: the sign is read, not the magnitude, because each step rebuilds the atlas.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | full (`2febf905`)          | `fonts.reload(size ± 2)`; `bumpFontSize`                                                     |
| FNT4  | Glyphs outside the base atlas (icons, higher-plane, CJK) must load on demand: draw requests a codepoint, atlas grows after `EndDrawing`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | full (`efa6cd7f`)          | `fonts.flushPending()` after `EndDrawing`                                                    |
| FNT6  | Monospace column width (v1) counts one column per codepoint — **wide/CJK/tab characters count as 1 cell**, so wide glyphs may overlap.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | partial                    | `gui_text.columnWidth` (documented v1 limit)                                                 |
| FNT7  | Color-emoji / flag glyphs render as tofu (raylib/stb_truetype ignores CBDT/COLR); monochrome symbols render.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | partial                    | raylib limitation (documented in `raylib-text`)                                              |
| FNT9  | CJK renders only when the **primary** face covers it — on-demand atlas growth asks only the primary; fallback atlases are frozen at the base codepoint set (`FNT14`). The bundled default primary (Maple Mono NF CN, `FNT13`) covers CJK, so the gap is confined to hosts where that family is absent and no CJK `--font` is chosen. (`--font-codepoint-map` **is** exposed now — the unified `ui-app` CLI carries it, defaulting to the Uiua386 map — but a map is a per-range override, not a coverage fallback.)                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | partial                    | `FontSet.resolveFace`; `gui_options.GuiCliFields`                                            |
| FNT10 | Underline is drawn as a single straight rule; the shaped `TermStyle`'s curly/dotted/double/dashed styles and independent underline color are not rendered.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | partial                    | `mapStyle` (underline bit only)                                                              |
| FNT11 | **Per-style faces** are explicitly configurable, ghostty-style: `--font-bold`, `--font-italic`, `--font-bold-italic` each take a family, fontconfig pattern, or font file; unset faces auto-detect from the `--font` family. **hue never fakes an italic** — a missing italic face renders upright (a synthetic slant/shift breaks grid alignment; tokens italic under one theme but not another appeared to move between themes). Bold without a bold face still double-strikes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | full                       | `FontSet.FaceOverrides`; `loadFaceOverride`; `pickStyledFace`                                |
| FNT12 | **Variable fonts**: selecting a named instance / axis values (wght/slnt/ital) for each styled face. fontconfig can resolve named instances; per-axis control needs FreeType variation APIs the raylib loader does not expose.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | researched                 | `FNT11`; raylib `LoadFontEx` limitation                                                      |
| FNT13 | **One bundled font set, resolvable identically on every platform.** The fonts hue ships are defined once — `nix/packages/fonts.nix` (`sparkles-fonts`: Maple Mono NF CN in all four styled faces, FiraCode Nerd Font Mono Regular+Bold, DejaVu Sans Mono in four faces, Uiua386, each with an `fc-query` `.charset` sidecar) — and the Android asset bundle copies that derivation verbatim. A desktop install must be able to run **font-deterministically** from the same bundle: a `hue-bundled` nix package ([`BLD5`](./feature-requirements.md#build-and-packaging-bld)) points the binary at the bundle as its default font directory (an env-var default the explicit `--font-dir` overrides — the `SPARKLES_TS_GRAMMAR_PATH` idiom), so `nix run` renders the same glyphs as the APK on a host with no fonts installed. Plain `packages.hue` stays the minimal-closure variant and resolves from the host font database.                                                    | partial                    | `fonts.nix`; `FontSources`; `--font-dir`; `BLD5` (package pending)                           |
| FNT14 | **Extended-Unicode symbol fallback (JuliaMono).** The regular fallback (DejaVu Sans Mono) must be complemented by a high-coverage **symbol fallback** — JuliaMono (OFL, `pkgs.julia-mono`, ~3.2 MB Regular face; mathematical alphanumerics, operators/arrows supplements, APL) — bundled in `sparkles-fonts` and consulted for codepoints neither the primary nor DejaVu covers. Two routes: **(v1)** a default `--font-codepoint-map` entry over ranges the primary family lacks (mathematical alphanumerics U+1D400–U+1D7FF and friends) — exactly the shipped Uiua386 idiom, works with today's engine; **(the honest fix)** fallback faces gain **coverage-driven on-demand atlas growth** — today every fallback is loaded with the fixed base codepoint set and never grows, so `resolveFace` can only ever serve base-set glyphs from a fallback no matter what the font file covers, and the `.charset` sidecars the bundle already writes are read for the primary alone. | not started                | `loadFallbacksFromDirs`; `resolveFace`; `loadFaceCharset` (primary-only); `uiuaCodepointMap` |
| FNT15 | **Ligatures are a non-goal for the per-codepoint renderer.** The raylib atlas is keyed by codepoint — there is no shaping pass, and `calt`/`liga` ligature glyphs are unencoded (no codepoint), so `LoadFontEx` cannot even load them, let alone select them from context; a ligature also spans cells, which the fixed cell advance, selection, and hit-testing (`RND6`, `SEL*`) are built against (the reason kitty refuses ligatures; ghostty ships HarfBuzz to render them). What **is** supported is baked in at build time: the bundled Maple Mono is rebuilt with its single-codepoint alternates frozen (`cv03`/`cv08`/`cv61`/`cv64`, `ss07`–`ss10`, `zero` — `nix/packages/maple-mono`), which is precisely the feature set freezing can deliver without a shaper. Real ligatures wait for a shaping-capable backend (the planned Skia/HarfBuzz peer backend) and a multi-cell glyph model.                                                                                | non-goal (v1) / researched | `nix/packages/maple-mono`; raylib `LoadFontEx` limitation                                    |

## CRT post-processing shader & cursor reactivity (`CRT`)

A GPU post-processing effect pipeline implemented in `sparkles:ui-raylib` (`crt.d`) and integrated into `hue --gui` (`gui.d`).

| ID    | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Status | Traces to                                                                                                                               |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| CRT1  | **Curvature & vignette**: The CRT shader must apply radial barrel distortion, corner rounding, and outer edge vignetting to simulate a convex cathode ray tube display.                                                                                                                                                                                                                                                                                                                                                       | full   | `sparkles.ui_raylib.crt`; `CrtEffect.apply`                                                                                             |
| CRT2  | **Scanlines & shadow mask**: The shader must render horizontal scanline modulation and RGB aperture phosphor shadow mask patterns.                                                                                                                                                                                                                                                                                                                                                                                            | full   | `sparkles.ui_raylib.crt` shader source                                                                                                  |
| CRT3  | **Dual-pass bloom & phosphor glow**: high-luminance pixels must bleed into adjacent regions via bright-pass extraction and a separable gaussian blur, with configurable intensity, threshold and radius. The blurred result must be sampled at the same warped `uv` as the content, so the glow curves with the tube rather than floating flat above it.                                                                                                                                                                      | full   | `crt.d` `bloomShaderBody`; `CrtEffect.runBloomPasses`; `bloomIntensity`/`bloomThreshold`/`bloomRadius`; `appearance.crt.bloomIntensity` |
| CRT4  | **Chromatic aberration**: Radial chromatic aberration must split RGB channels towards screen edges.                                                                                                                                                                                                                                                                                                                                                                                                                           | full   | `crt.d` chromatic aberration uniform                                                                                                    |
| CRT5  | **Pointer reactivity**: the curvature's apex must follow the pointer when tilt is enabled, so the surface is flat directly under it and the far side curves away; with the pointer in a corner that corner straightens out. (An earlier draft specified a `flattenRadius`/`flattenStrength` mechanism; the shipped model is the tilted apex, which has no such parameters.)                                                                                                                                                   | full   | `crt.d` `curve`; `mouseTilt` uniform; `CrtProjection.tilt`                                                                              |
| CRT6  | **Pointer mapping & in-shader rendering** (`appearance.pointer.mode = software`, the default): mouse pointer motion is linear in texture space (UI coordinates), translating to non-linear curved motion in screenspace. When CRT is active, the host compositor cursor is hidden and the pointer is rendered in-shader at the corresponding curved surface coordinates. Input events operate directly in linear texture space. `PTR1` inverts this.                                                                          | full   | `crt.d` cursor rendering; `runGui` cursor management                                                                                    |
| CRT10 | **Screen fit**: the projection must seat the midpoint of each texture edge exactly on the corresponding screen edge at $(B any) curvature — `fit = 1 / (1 + k/4)`, since the bend displaces a point at radius `r` by `(1 + k*r*r)` and an edge midpoint sits at `r = 1/2`. A flat screen (`k = 0`) is therefore a 1:1 blit, and the only part of the window without an image is the rounded corners. Exact for a centred apex; an off-centre one (tilt) deforms the four edges unequally and no single scalar seats them all. | full   | `crt.d` `curve`; `crt_projection.d` `CrtProjection.curveStep`; `ui_raylib.crt_projection.curve.seatsEachEdgeMidpointOnItsScreenEdge`    |
| CRT8  | **Magnifier lens centred on the pointer**: the magnification lens must be applied in texture space, after curvature, so the point it leaves fixed is the very one the in-shader cursor (`CRT6`) is drawn at. Applied before curvature the two centres diverge with distance from the middle of the screen.                                                                                                                                                                                                                    | full   | `crt.d` `mouseMagnify` block; `CrtProjection.mapScreenToUi`; `ui_raylib.crt_projection.magnifierLensIsCentredOnTheCursor`               |
| CRT9  | **UI-reactive boxes come from the paint site's own origin**: every `CrtUiContext` rect must be derived from the same origin the widget is painted at (`pickerOriginCol`/`pickerOriginRow` for the picker), not from a second, independently re-derived centring.                                                                                                                                                                                                                                                              | full   | `gui.d` `CrtUiContext` block; `picker_view.pickerOriginCol`                                                                             |
| CRT7  | **Live toggle & uniform binding**: `F12` must toggle the CRT shader at runtime; uniform parameters update per-frame without pipeline re-creation.                                                                                                                                                                                                                                                                                                                                                                             | full   | `runGui` `KEY_F12`; `CrtEffect.end` uniform upload                                                                                      |

## Pointer (`PTR`)

Which pointer the window shows, and therefore which coordinate space pointer
input arrives in. The two modes are each internally consistent and pick opposite
invariants; `appearance.pointer.mode` is the choice, not a tweak.

| ID   | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Status | Traces to                                                                                                                        |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------- |
| PTR1 | `appearance.pointer.mode` selects `software` (default — hue draws the cursor in-shader, `CRT6`) or `system` (the window system draws its own). Under `system` the compositor cursor must **not** be hidden and the shader must draw **no** cursor; the two are one condition, so switching mid-run restores the other on the next frame.                                                                                                                                                                                                                                                              | full   | `settings.PointerMode`; `CrtEffect.systemPointer`/`drawsOwnPointer`; `Window.pointerVisible`; the negative `cursorShape` uniform |
| PTR2 | Under `system`, pointer input arrives in **screen** space and must be translated to the UI point rendered under it. Magnification is not applied — the lens is centred on the pointer and leaves that point fixed, so it cancels exactly; tilt's apex is that same point, so the map must be resolved to its own fixed point rather than run once against the previous frame's value.                                                                                                                                                                                                                 | full   | `CrtProjection.mapPointerToUi`; `ui_raylib.crt_projection.mapPointerToUi.resolvesTheDistortionsCentredOnIt`                      |
| PTR3 | A warped image does not fill its window, so some screen positions have no UI point under them — the tube's rounded corners, `CRT10` having seated the edges flush (1.2% of the window at the default curvature, 7.7% at the maximum). Uncaptured, a move there must arrive as `leave` — hover clears rather than sticking — and a press must be swallowed, and therefore must not start a capture. **Captured**, every event must be clamped onto the surface and delivered, and a `release` must be delivered whatever the capture state, or a drag dies at the bezel and the button never comes up. | full   | `sparkles.input.surface.PointerCapture`; `gui.admitEvent`                                                                        |
| PTR4 | The translation must happen once, at the event intake, not per consumer: `rawPointerPos`, the frame fold and the dock's own drain all read the same `evBuf`. `HUE_GUI_POINTER` stands in for a window-system event nobody sent, so it is **synthesized as one** and put through the same intake — routing included, not merely the coordinate map. A harness that exercised a second path would certify behaviour the product does not have, by construction rather than by drift.                                                                                                                    | full   | `gui.admitEvent`; `sparkles.input.surface.admitOntoSurface`; `input.surface.admitOntoSurface.mapsRewritesAndDrops`               |
