# Web (`WEB`)

_**Status:** proposed · **Date:** 2026-09-21 · **Owner:** `sparkles:docs`
(the emitter); `docs/.vitepress/theme` (the consumer) · **Scope:** how the
framework externalises a theme as CSS custom properties, how the generated
stylesheet reaches the two documentation sites, and what "responsive" means in
cells._

Sequenced **second** after the TUI ([overview](./index.md#target-sequencing)):
the web has the most established design-system practice, and the docs sites
are the first consumers of [Sparkles](./sparkles-theme.md).

| ID     | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                            | Status      | Traces to                                                      |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- | -------------------------------------------------------------- |
| `WEB1` | The **framework declares** the CSS custom properties: one `--spk-<path>` per token (`text.primary` → `--spk-text-primary`, [`TOK2`](./SPEC.md)), and one `--spk-<path>-<state>` per state override a theme sets ([`TOK4`](./SPEC.md)). Components' CSS reads `var(--spk-x-hover, var(--spk-x))`, so an unset state falls through exactly as `TOK4` requires. The names are produced by `cssName`, never typed in a stylesheet by hand. | proposed    | `tokens.d` `cssName`; `sparkles.docs.assets`                   |
| `WEB2` | The **theme defines the values**: `sparkles.docs.assets` emits one stylesheet from a `Theme` — light values unscoped, dark values under `html.dark` and `@media (prefers-color-scheme: dark)` — including the syntax channel (`.syn-*`, as today) and the callout colors, which become `status.*` tokens instead of hex literals.                                                                                                      | partial     | `assets.d` `themeStylesheet` (syntax only; callouts hardcoded) |
| `WEB3` | **VitePress consumes, never authors.** `custom.css` maps `--vp-c-brand-*`, `--vp-c-bg*`, `--vp-c-text-*` and friends _from_ `--spk-*` in one mapping block; the generated stylesheet is imported from a build artifact (`ci --emit-css` or a `sparkles:docs` step), and a test diffs the committed copy against a fresh emission so the site cannot drift from the theme (the `THM5` lockstep pattern, generalised).                   | not started | `docs/.vitepress/theme/custom.css` (hand-authored today)       |
| `WEB4` | The **`html_semantic` interpreter** ([`TGT4`](../ui/backends.md)) emits class names derived from slot paths (`.spk-text-primary`) and its stylesheet is the same emitted file, so a `ui-gallery` page rendered to HTML and a docs page share one design language byte-for-byte.                                                                                                                                                        | partial     | `interp/html_semantic.d` (own class scheme today)              |
| `WEB5` | **Responsive breakpoints are in columns**: 80, 120 and 160, mapped to px through the mono face's `1ch` so the same layout rules the TUI applies at those widths (`UGL15`'s 60-column sidebar collapse, `UGL5`'s sizes) hold on the web. Container queries over `ch` units, not device px.                                                                                                                                              | not started |                                                                |
| `WEB6` | The site's **type stack** is a token (`font.sans`, `font.mono`), the mono stack listing the bundled Nerd Font families first as `custom.css` does today; the sans face is chosen with the Sparkles theme ([`SPK4`](./sparkles-theme.md)).                                                                                                                                                                                              | not started | `custom.css` `--vp-font-family-*`                              |
