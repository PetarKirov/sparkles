# Testing — oracles and evidence

_**Date:** 2026-09-21 · The trace is `requirement → falsifying scenario →
oracle → scoped evidence`. Each oracle states its independence from the
implementation; a round trip alone is not one._

## Oracles

| ID   | Oracle                                                                                                                                                                                                                                                                                                                                                                                                                     | Independence                                                                                                                                                        | Covers                                           |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| `O1` | **The style guide is the gallery.** `ui-gallery --render --profile {baseline,enhanced,full}` paints each catalogued page headless; the output is embedded as an `ansi` fence in the public style-guide pages (`docs/design-system/…`) and `ci --verify` checks it. `ui-gallery` takes the role Storybook has for web design systems: the canonical rendering of a component is the one the reference application produces. | The fence is reviewed by a person once when blessed; the verifier catches drift. Independence is the human review of the golden, not the renderer.                  | `CAP5`, `ACC4`, `GLY2`/`GLY3`, `TOK6` (visually) |
| `O2` | **Contrast.** A WCAG 2.x relative-luminance + contrast-ratio implementation in the test tree, validated against the published example pairs from the WCAG technique documents (pinned), computes `ThemeConformance` for every built-in and every derived palette.                                                                                                                                                          | Published vectors; the tone model in `color-derivation` is a second, independent path (CIE L\*) whose ordering must agree.                                          | `ACC1`, `ACC2`, `SPK2`                           |
| `O3` | **Slot discipline.** For each component, build its display list over a fixture model and assert `slotsWithin(ops, Component.slots)`.                                                                                                                                                                                                                                                                                       | The declared set is authored by hand per component; the test is a set membership over ops — a second implementation of nothing.                                     | `TOK6`                                           |
| `O4` | **Theme file.** Load the pinned DTCG specification's own example documents and the 36 exported built-ins; assert structured errors on a corpus of deliberately malformed files (cycle, dangling alias, wrong `$type`, out-of-range color); round-trip canonical equality.                                                                                                                                                  | Upstream examples are an interoperating peer; the malformed corpus is hand-derived. Round trip alone is explicitly insufficient and is paired with the peer corpus. | `FMT1`–`FMT6`                                    |
| `O5` | **Capability probing.** A scripted pty peer replies (or does not) to each query with recorded real-terminal transcripts (kitty, Ghostty, foot, xterm, tmux-wrapped); `detectTermCaps` + the tui probe must produce the expected `TargetCapabilities`, and a silent peer must return within the timeout with the sentinel path taken.                                                                                       | Transcripts are captured from real emulators at pinned versions, not synthesised from the parser.                                                                   | `CAP3`, `CAP7`, `CAP8`                           |
| `O6` | **CSS lockstep.** Emit the stylesheet from `Theme`, diff against the committed copy VitePress imports; assert every `--spk-*` name equals `cssName(slot, state)`.                                                                                                                                                                                                                                                          | The committed copy is reviewed; the name check is against the one function `TOK2` mandates.                                                                         | `WEB1`–`WEB3`                                    |
| `O7` | **Projection tables.** `projectBorder` and the sub-cell ladders are checked cell-by-cell against a hand-written table for every `(width, style, radius, tier)` combination — exhaustive, since the domain is small.                                                                                                                                                                                                        | Hand-derived expected glyphs.                                                                                                                                       | `GLY2`, `GLY2a`, `GLY8`, `CAP9`                  |

## Omitted combinations

`O1` renders three profiles, not the 2^n flag combinations; the projection
functions (`O7`) are exhaustive instead, so a flag combination outside the
profiles is covered at the function level, not the page level. `O5` covers
five emulators; others are `unverified` until a transcript is captured.
