# Glyphs & typography (`GLY`)

_**Status:** proposed · **Date:** 2026-09-21 · **Owner:** `sparkles:ui`
(`GlyphSet`, the projections), `sparkles:ui-tui` (cell painting),
`nix/packages/fonts.nix` (the bundled faces) · **Scope:** what a cell target
draws when the theme asks for something a cell cannot hold — sub-cell borders,
radius, weight, icons, headings — and the type model that is the same on every
target._

## Glyph tiers

| ID     | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                      | Status  | Traces to                                                                                                                                                       |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GLY1` | Glyphs are organised in **nested tiers**: `ascii ⊂ boxLight ⊂ boxFull` (heavy, double, rounded, dashed) `⊂ blocks` (per `blocks` level) `⊂ braille ⊂ nerdFont`. A theme names a preferred charset per role (frame, rule, tree guide, thumb, marks); the target's declared tier **caps** it, and the capped choice is the published substitution ([`CAP6`](./capabilities.md)). Violation: a glyph outside the target's tier reaching the canvas. | partial | `glyphs.d` `needOf`/`admits`/`fallbackOf`/`projectGlyph`; `ui_tui` `GridCanvas` projects every glyph; per-role theme preferences only for marks (`MarkCharset`) |

## Border projection

A bordered box on a cell target **always reserves one cell** per drawn edge;
weight, style and radius select the glyphs in that cell. Sub-cell edges are for
things that do not own a cell: rules, separators, scrollbar thumbs and progress
fills.

| ID      | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Status  | Traces to                                                                                                                                |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `GLY2`  | A px-typed border projects onto a cell target by one pure function of `(BoxBorder, radius, TargetCapabilities)`: width `0` → no edge; width `1` → the light family; width `≥ 2` → the heavy family; style `double_` → `boxDouble` (`═║╔╗╚╝`; weight and radius are lost there and reported); `dashed` → `╌╍╎╏`, `dotted` → `┈┉┊┋`, each in its weight; radius `> 0` → arcs (`╭╮╰╯`), which exist only for the light families: a heavy rounded request keeps its arcs drawn light and reports the weight lost (D31), a double rounded one keeps square corners and reports the radius lost. Below `unicode`, everything is `+-\|` — except dotted, which keeps `.`/`:`. The table is exhaustive and tested per cell. | full    | `tokens.d` `projectBorder`, `boxGlyphs`, test `ui.tokens.projectBorder.table` (`O7`); `ui_tui` `drawBoxBorder`; `cells.d` tables derived |
| `GLY2a` | **Sub-cell edges.** Where `blocks ≥ half`, a hairline rule or separator may be drawn as a thin edge on the cell boundary (`▏▕▔▁`), and a thumb or fill as eighth-blocks (`▏▎▍▌▋▊▉█` / `▁▂▃▄▅▆▇█`), so a 1px rule need not consume a whole cell of `─`. Which elements use sub-cell edges is a theme choice per role (`GLY1`); the mechanism is the target's. Violation: a sub-cell glyph emitted on a target declaring `blocks = none`.                                                                                                                                                                                                                                                                             | partial | `glyphs.d` ladder (eighth-block bars thin to strokes at `blocks = none`); `ui_tui` accents; the sub-cell hairline rule is not drawn yet  |

## Status marks

| ID     | Requirement                                                                                                                                                                                                                                                                                                                                                    | Status | Traces to                                                                          |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ | ---------------------------------------------------------------------------------- |
| `GLY3` | The glyph channel carries one **mark** per `status.*` token and per task state (`WGT25`), in three charsets — `nerdFont`, `unicode` (`✔ ✖ ⚠ • ○ ◐ ┄`), `ascii` (`+ x ! * o ~ .`) — and `ACC3` reads them. A mark is one cell wide in every charset, so columns do not shift between charsets, and the charsets' forms agree with the fallback ladder (`GLY1`). | full   | `glyphs.d` `Mark`/`markGlyph`; `components/theme.d` `StatusGlyphs` reads the table |

## Fonts and icons

| ID     | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Status      | Traces to                                              |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- | ------------------------------------------------------ |
| `GLY4` | A **Nerd Font is baseline on GUI and Web** (the bundled `sparkles-fonts` set, [`FNT`](../hue/gui.md)) and **optional on the TUI** (`nerdFont` capability, configured — it cannot be queried). The Nerd Font version is **the one the flake's pinned nixpkgs ships** (`nerd-fonts.*`, 3.5.0 at the time of writing); the design system does not pin separately. The icon table the toolkit uses (`nf-*` names → code points) is generated from that release's `glyphnames.json` and checked in, so a nixpkgs bump that moves a code point is a golden diff, not a silent glyph swap. | not started | `nix/packages/fonts.nix`; proposed `sparkles.ui.icons` |
| `GLY7` | On targets with `proportionalText`, `FontRole.docs` may be a **proportional face**: layout stays in cells, the run is measured in px and wrapped or clipped **inside its cell rect**, and the cell rect is what hit-testing and selection see. A cell target renders the same run monospace in the same rect. Violation: a docs run whose painted extent leaves its layout rect on any target.                                                                                                                                                                                      | not started | `raylib-text`, `ui-raylib`; `display_list.d`           |

## Typography and sizing

| ID     | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Status      | Traces to                                                                       |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- | ------------------------------------------------------------------------------- |
| `GLY5` | The **type hierarchy is expressed in attributes first**: heading levels map to (weight, color token, underline/overline, a leading glyph) so a heading is distinguishable at `baseline`. Where `textSizing` is declared, a heading **may** additionally render at scale via OSC 66; the fallback **preserves layout** (the same rows and columns are consumed) so a document does not reflow between a sizing and a non-sizing terminal. The sizing mechanics are the [text-sizing proposal](../../research/tui-libraries/text-sizing/sparkles-proposal.md), which is **not accepted**; this row's entry condition is that proposal's M0. | not started | `source_view.markdown` heading icons (today); `TextStyle.fontScale`             |
| `GLY6` | **Width is measured in grapheme clusters** (UAX #29) via `sparkles.base.text`, never `wcwidth` per code point; East Asian ambiguous width is a user setting; under `graphemeClusters` (mode 2027) the terminal's segmentation is trusted, otherwise the toolkit's is used and the two are reconciled by the libghostty width oracle in tests. Bidi and shaping are a **non-goal** on the cell target.                                                                                                                                                                                                                                     | partial     | `base.text` graphemes; ghostty width oracle (memory: `ghostty-vt-width-oracle`) |

## Sub-cell rendering and media

| ID     | Requirement                                                                                                                                                                                                                                                                                                          | Status  | Traces to                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GLY8` | Meters, sparklines and scroll thumbs use the **finest sub-cell unit the target declares**: eighth-blocks for one-dimensional fills, `braille` (2×4) for plots, `blocks` level for 2-D rasters. Each has an exact fallback ladder down to `ascii` (`#` / `=` / `-`), and the ladder rung chosen is reported (`CAP6`). | partial | `components/meter.d`, `progress.d`; eighth-block fills fold by the `GLY1` ladder and are reported (`blocks-folded`)                                                                                                                                                                                                                                                                                                                                 |
| `GLY9` | An image renders by the ladder **protocol → block raster (`blocks` level) → braille → alt text**; the placeholder's cell size is the same on every rung so layout never depends on which rung a target reached (`WGT22`).                                                                                            | partial | the cell rungs: `sparkles.ui.image_raster` (`imageRungOf`, `paintImageRaster`: half blocks, quadrants, sextants, braille; two colours per cell by an area-sampled split), drawn by `ui-tui`'s grid and by a narrowed `ui-raylib` window; `degradation.d` rows `image-rastered`/`image-as-alt`. The protocol rung, kitty and sixel: `IMG5` (`sparkles.tui.images`, `sparkles.tui.sixel`, `sparkles.tui.probe`). Not yet: octants (sextants stand in) |
